# 图片识图搜索研究记录

状态：**暂缓实现**。按用户 2026-10-18 的决定，本轮研究结束，不继续抓包、接入或推进拖拽验收。已有入口与降级代码保留，三家自动上传保持禁用。本文件留作后续参考。

## 结论

Google 官方页面上传图片可以正常得到识图结果，但将已观察到的上传地址和文件字段用于本机页面的跨站表单提交，两次均返回 403。本次没有得到可供扩展稳定使用的自动上传方案。

这不等于证明 Google 没有任何外部识图接口，也不能推断 Bing、搜狗同样不可用；本次没有调研公开 API 文档，后两家没有抓包。网页内部上传端点与正式对外 API 应分别评估。

## 已确认的事实

| 项目 | 观察结果 |
| --- | --- |
| 环境 | 用户自己的 Chrome、已有登录环境，2026-10-18 |
| 官方入口 | Google Images → Search by image → upload a file |
| 测试图片 | 生成的 256×256 PNG：绿色方块、浅色圆形与 Easy Tab test 文字，不含私人内容 |
| 官方结果 | 成功进入 Google Search 的 Visual matches，并识别出测试文字及图形 |
| 实际上传请求 | `POST https://lens.google.com/v3/upload` |
| 请求类型 | `multipart/form-data` |
| 查询参数名 | `ep`、`st`、`authuser`、`hl`、`vpw`、`vph`；观察到 `ep=gsbubb` |
| 文件字段 | 官方页面文件输入名为 `encoded_image` |
| 官方响应 | 303，随后导航到 Google 识图结果 |
| 跨站复现一 | 本机测试页导入项目 `submitMultipart`，用 DataTransfer / File 上传同一 PNG，只带 `ep=gsbubb`，返回 403 |
| 跨站复现二 | 补齐已观察到的公开查询参数，重新生成时间戳，仍返回 403 |

复现证据：[Google 403 截图](google-upload-403.png)。原始 HAR 仅保存在临时目录，未纳入项目；文档不保存 Cookie、账号或结果页会话标识。

## 尚未确认的部分

- 导出的脱敏 HAR 没有请求体；文件字段来自官方页面输入元素，不能据此断言已经还原全部表单字段。
- 403 的具体原因未知。来源检查、遗漏字段或其他服务端校验都只是可能性，不能据此认定为 CORS 问题。
- 复现来源是本机 HTTP 页面，未直接验证 `chrome-extension://` 来源，因此不能将该结果概括成“扩展一定无法提交”。
- 未验证匿名环境、首次同意页、不同文件格式，以及用户原生拖拽的完整流程。
- Bing Visual Search、搜狗识图没有完成官方请求抓取与复现。

## 项目保留状态

- `js/search/imageSearch.js` 的 `verifiedUploads` 三项均为 null，自动上传禁用；保留通用 multipart / base64 表单工具。
- 已有相机 SVG、选文件入口、拖图来源提取、图片类型与 10MB 限制、下载错误处理继续保留；文字输入按 Enter 搜索。
- 当前降级路径为：准备图片 → 复制图片并打开官方图搜页面 → 用户在相机入口粘贴；也可保存图片后手动上传。这不等于自动识图已完成。
- 网页图片下载受 CORS / 网络限制；剪贴板和新标签页打开受浏览器策略影响。没有新增权限或依赖。
- 最后一次 `npm test`：45 项全部通过。覆盖来源提取、下载限制、剪贴板调用顺序、表单构造、同步提交与清理、未验证适配器禁止提交；这些 Node 测试不证明第三方服务可用。
