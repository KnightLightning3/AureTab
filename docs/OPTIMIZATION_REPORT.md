## 二、本次已落地的优化（供对照）

这些改动已进入 `5b2e6d3`，报告后续建议不重复计入：

- **保存流程**：编辑、拖拽、偏好统一走串行队列，并在保存前重新读取存储，避免旧快照覆盖并发修改；自身写入不再触发第二次完整渲染。
- **拖拽排序**：修正「向前移动」插入位置，落到相邻下一项不再产生无意义保存。
- **渲染**：分组按钮按需更新；自定义图标由分类器直接读 IndexedDB，不再每次渲染都预读。
- **图标兜底**：本地图标/自定义图标失败或小于 32px 时继续尝试 favicon 链，而不是停在文字占位。
- **IndexedDB**：处理连接关闭、动作抛错时中止事务、写入超时；壁纸仅在超时时回退原图。
- **备份**：导出预览与壁纸选择保持一致；导入忽略无引用的图片；旧备份缺壁纸 Blob 时回退为「无」。
- **校验**：偏好缺字段时合并默认值，未知枚举回退而不是让新标签页白屏；保留图片 ID 被拒绝；大体积 base64 不再 `trim()` 复制。
- **图搜**：拒绝 SVG、内网/回环地址、带账号信息的链接；提前取消响应体；剪贴板转换限制画布尺寸；表单提交抛错也清理。
- **搜索**：孤立 UTF-16 代理项与未知引擎 ID 不再抛错。
- **滚轮/侧栏**：长分组列表可原生滚动，仅在边缘切换分组；布局测量按帧合并。
- **CSS**：删除被后续规则覆盖的失效媒体查询；壁纸模糊不再在视口边缘产生透明光晕。
- **极简模式切换**：不再整页淡入淡出，也不再使用 View Transitions 快照；搜索内容保持原尺寸，用 FLIP 平移到居中位置，只有顶栏与站点区淡出/淡入。
- **可访问性**：弹窗补 `aria-labelledby`，设置面板补 `role="dialog" aria-modal` 并让背景 `inert`；图标、分组图标、壁纸选择支持方向键与 roving tabindex。

## 三、建议加入的优化

### A. 流畅度与性能

#### A1. 去掉每个 `.site-icon` 的 `backdrop-filter`（P1）

**现状**：`css/themes.css` 给每个图标加 `backdrop-filter: blur(8–12px)`，而图标背景色本身已有 0.75–0.82 的不透明度，模糊几乎不可见。一个 60 站点的分组在 2x/4K 屏上会同时维持几十个背景采样层；分组切换的 220ms 位移动画、滚轮边缘拖拽、鼠标扫过图标时都会触发重新采样。

**建议**：移除 `.site-icon` 的背景模糊，改为把 `--icon-bg` 提到约 0.9；只保留搜索框、菜单、设置面板的单层模糊。若必须保留玻璃质感，可把模糊收敛到网格底板的一层伪元素，而不是每块图标各一层。批注：保持玻璃感，可以收敛成底板伪元素

**收益**：网格动画与滚动更接近合成器动画；GPU 内存与耗电下降。
**风险**：低，属于细微视觉差异，建议先在 4K 与集显机器上对比截图。

#### A2. 图标加载限流与离屏懒加载（P1）

**现状**：`renderGrid` 对每个站点立即启动 `load()`，每个站点最多顺序尝试 3 个远程源；首次打开 60 站点分组会同时产生大量图片请求与解码，和壁纸解码争抢主线程；快速切换分组时旧站点的加载仍会继续。

**建议**：
- 用一个 4–6 并发的任务队列包裹 `showClassifiedIcon`；
- 对首屏以下的图标用 `IntersectionObserver` 延迟启动；
- 在 `load()` 内检查 `root.dataset.group === key` 或使用代际计数器，分组已切换就提前退出。批注：可以，但是要注意，从远程下载下来的图标，之后就不要再请求了

**收益**：首屏骨架更快、分组切换更稳，弱网下更明显。

#### A3. 壁纸解码限制尺寸（P1）

**现状**：`compressImage` 先 `createImageBitmap(file)` 全尺寸解码，再缩放到 1920。一个 12000×8000 的照片会在主线程分配约 384MB RGBA，可能卡死或 OOM。

**建议**：先读取图片头获取宽高（`ImageDecoder` 或轻量 header 解析），再调用 `createImageBitmap(blob, { resizeWidth, resizeHeight, resizeQuality: 'high' })` 直接按目标尺寸解码；无法预读时，在解码后加像素上限保护。长期可迁移到 Worker + `OffscreenCanvas`。（批注：这种解码并缩放是否会导致：上传高清图片后表现为低清图片？现在背景被设置成了纯静态，可以考虑移除压缩选项。与此同时像素上限保护可以不加，直接把上传部分的加号ui改成：建议小于XXMB，上传过大图片是用户的问题，会导致的卡顿和卡死由用户自己承担）

**收益**：上传大图不再冻结新标签页。

#### A4. 极简模式切换：内容位移而非整页快照（已落地）

本次已移除 `startViewTransition` 与整页淡入淡出。现在切换时：

- 搜索内容（时钟 + 搜索框 + 极简按钮）保持原尺寸，用 FLIP 平移到视口居中位置；
- 只有顶栏与站点区淡出/淡入，壁纸完全不参与任何快照；
- `prefers-reduced-motion` 下直接切换，不等待也不播放位移。

**后续可选**：把 140ms 淡出 + 280ms 位移按设备性能分档（低端机缩短位移），或允许用户在设置中关闭切换动画。 批注：这个已经修改了，跳过这一条

#### A5. 减少网格动画期间的昂贵绘制（P2）

**现状**：`#grid` 在滚轮边缘拖拽和分组切换时被平移，`#grid` 内每个图标都有背景模糊（见 A1）。

**建议**：若短期保留图标模糊，可在 `#grid.wheel-pulling` 或分组动画期间临时关闭图标的 `backdrop-filter`，动画结束再恢复；更好的做法仍是 A1。批注：接受

#### A6. 给长列表加 CSS 隔离（P3）

**建议**：为 `.grid-viewport` 增加 `contain: layout paint`（或 `content-visibility: auto` 配合 `contain-intrinsic-size`），让屏幕外站点不参与布局与绘制。需先用 100+ 站点实测，避免与现有的高度测量逻辑冲突。
批注：改完后测试

### B. 数据可靠性与存储

#### B1. 资源垃圾回收（P0）

**现状**：`assetStore.delete` 目前只用于壁纸。删除/替换自定义图标、删除站点或分组、以及 `icon-cache:*` 分类缓存都会留下永久 Blob；扩展未申请 `unlimitedStorage`，长期使用后 IndexedDB 写入会开始失败。

**建议**（保守方案，兼顾多标签）：
1. **精确删除**：在站点/分组删除、图标替换、`removeIcon` 的保存成功后，对比新旧 `iconId` 集合，删除不再被引用的 `icon:<uuid>`；
2. **启动清扫**：在 `start()` 后异步执行一次，扫描所有 `icon:*` 与 `icon-cache:*`，保留当前数据引用 + 最近 N 天使用过的记录；
3. **多标签保护**：清扫前写入一个 `gcAt` 时间戳，若检测到其他标签在最近几分钟内写入过数据则跳过；或只在 `navigator.locks` 可用时持锁执行。

**收益**：避免存储耗尽导致的保存失败。
**风险**：误删正在被其他标签引用的 Blob；必须用上面的保护措施。

批注：接受，但是可以写一个时间记录，在出现更改后，等待约十分钟后再做垃圾清理
#### B2. `revision` 版本号与冲突合并（P0）

**现状**：本次已改为「保存前重新读取 + 队列串行」，大幅缩小了旧快照覆盖的窗口，但仍不是原子读改写；两个标签在毫秒级同时保存仍可能互相覆盖。

**建议**：在 `appData` 中加入单调递增的 `revision`（校验时保留），保存时比较读到的 revision 与存储中的 revision，不一致则重新读取并重放本次变更（最多重试 2 次）。`devicePrefs` 同理。

**收益**：多标签编辑真正安全；也为将来的 `storage.sync` 打基础。

#### B3. 图标缓存按内容失效（P2）

**现状**：分类缓存键是 `icon-cache:<source>`，记录的版本号只跟分类算法有关。站点 favicon 变化或随包图标更新后，旧图会一直显示；`suppliedBlob` 存在时缓存记录仍然优先。

**建议**：把内容指纹纳入缓存键（对自定义 Blob 用长度 + 简单哈希；随包资源把扩展版本号写进键），或在校验失败时用 `suppliedBlob` 覆盖缓存记录。配合 B1 的清扫避免旧键堆积。

批注：图标更新可以不加，期望是favicon不会经常变化，随包则可以更新

#### B4. 导入只校验一次（P3）

**现状**：选择文件时 `parseBackup` 已完整校验，`planImport` 又校验一次；大备份（含上百 MB base64）会重复扫描与正则匹配。

**建议**：让 `planImport` 接受已校验对象（例如不可枚举的 `VALIDATED` 标记），并对备份做一次深拷贝以避免重试时复用被改写的 ID。或者在文件读取阶段只做轻量结构检查，导入时做完整校验。

#### B5. 表单校验前置，失败不丢输入（P2）

**现状**：`editDialog` 在提交时先关闭，再由 `addSite` 校验 URL、文字图标长度等；失败后用户输入全部丢失。

**建议**：给 `editDialog` 增加 `validate` 回调，在关闭前执行；失败时在弹窗内显示错误并保留输入。至少应对「URL 非法」「文字图标超过 3 个字符」「分组名为空」这三类高频错误生效。

### C. 好用与可访问性

#### C1. 长按阈值拖动分组（P2）

**现状**：分组按钮同时承担「点击切换」和「拖动排序」，鼠标按住即开始拖动，容易误触。用户最初的需求也是「长按拖动」。

**建议**：`pointerdown` 后启动 250–350ms 计时器，到时才设置 `draggable = true` 并给出轻微视觉反馈；提前移动超过阈值（如 6px）则取消长按。触屏与鼠标共用同一逻辑。

#### C2. 侧栏的滚动与键盘可见性（P2）

本次已让分组列表在非边缘位置原生滚动，但 `scrollbar-width: none` 仍隐藏滚动条，用户不容易发现列表可滚动。建议在悬停/滚动时显示 3px 细滚动条，与网格一致；并为分组按钮补 `Home/End` 跳转。
批注：不需要按钮，同时，加入上下方向键切换分组的功能（方向键不影响组内拖动）

#### C3. 焦点环对比度（P2）

**现状**：frost 主题的 `--focus` 接近白色，在浅色默认壁纸上对比不足；`#sidebar` 的 `overflow` 会裁掉 4px offset 的焦点环。

**建议**：采用「内描边 + 外描边」双环（深色内环保证任意背景可辨），或把焦点环改为 `box-shadow: inset`；为滚动容器留出足够 padding。

#### C4. `grid-auto-flow: dense` 与 Tab 顺序（P2）

**现状**：2×2/横向图标会让后续小图标回填空位，视觉顺序与 DOM 顺序可能不一致，键盘 Tab 会跳跃。

**建议**：若键盘顺序重要，改成普通 row flow；若保留 dense，至少在每次重排后同步 `tabindex` 顺序，或提供「按视觉顺序」的焦点管理。

批注：测试后认为，这个问题影响不大。但是，tab选中图标周围会有一圈标记，在站点图标和分组图标中，靠近边缘时，这个标记会被外边缘截断，同样的事也发生在图标滚动的动画里，我建议把外边缘对显示的截断给关掉，

#### C5. 站点别名去重（P3）

`data/sites.json` 中 `tb`（贴吧/淘宝）、`db`（豆瓣/Dribbble）、`so`（Stack Overflow/360）、`dd`（钉钉/当当）等短别名对应两个站点，当前按 JSON 顺序决定结果。建议删除歧义较大的一侧，或在条目中加入显式 `priority`，让排序确定。

批注：建议修改成没有别名，编码部分更好处理，搜索部分这样也符合直观感受，不需要专门给搜索加这种快速歧义通道
#### C6. 统一命令入口（P3，可选）

在搜索框支持 `:` 前缀切换到「站点/分组/设置」命令（如 `:主题`、`:极简`），复用现有本地索引，不增加网络请求。对高频用户比多点一次设置更顺手；实现上只需一个轻量解析器与现有动作绑定。

批注：不需要这个功能，可能会影响搜索本身

### D. 美观与视觉一致性

#### D1. 壁纸缩略图升级（P3）

当前缩略图直接显示完整 SVG，比例合适但缺少「当前选中」的层次。建议：选中项加 1px 强调描边 + 轻微内阴影（批注：现在是选中略微放大，这个功能暂不需要）；「本地图片」在已上传时显示真实缩略图（从 IndexedDB 生成 object URL），而不是固定「＋」。

`css/themes.css` 中仍有部分硬编码颜色（如 `.group-button.active` 的 `#dfe8dc`、图标阴影）。建议全部改为主题变量，便于新增主题和暗色适配；同时为每个主题定义 `--focus-ring-inner/outer`（配合 C3）。

## 四、明确不建议加入

为守住「轻量、零依赖、权限最小」的边界，以下方向不建议：

- **引入框架/构建链**（React、Vite 等）：当前 1900 行原生代码，收益低于维护成本。
- **在线图标搜索、第三方图标 API**：与规格书第十节冲突，且增加权限与隐私面。
- **`host_permissions` 换取 favicon 直读**：会扩大权限提示；现有 `<img>` 链已能工作。若确实需要实心铺满的自动分类，可只对 Google/DDG 两个域名申请最小 host 权限，并作为可选开关。
- **把 Blob 写入 `storage.sync`**：超出 8KB/项限制，必然失败。
- **为图标做虚拟滚动**：在 10000 站点上限下才需要，当前 CSS 流式布局更简单。
